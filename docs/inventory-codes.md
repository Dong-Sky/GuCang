# 实物自动编号与选填名称

## 规则

- 编号归属 `item_instances`，不替换 UUID、不放进共用的款式名称。同款多件分别编号。
- 每个家庭空间独立递增，家庭成员共享同一个计数器。首次保存时分配，包含快速暂存。
- `inventory_number` 为数据库整数序号；`inventory_code` 为生成列，格式 `GC-` + 至少6位数字。
- `GC-999999` 后为 `GC-1000000`，不截断、不统一重排旧号。代码中按数字排序。
- 数据库禁止修改编号或将实物换到其他谷仓。编辑资料、移动、取出、归位、回收站及恢复保持原号。
- 计数器独立于现存记录，删除最大号码也不回退。号码允许有空缺，不等于现存收藏数量。
- 保存失败重试复用原 UUID；数据库在家庭计数器锁内检查已有实例，兼容并发 upsert，不重复发号。
- 新收藏名称可留空，在「补充名称（选填）」中按需填写。旧名称不自动清空或覆盖。
- 完整度按 IP、品类及这一件的位置判断，不要求名称。款式只维护共享资料的完整度，位置单独按实例计算，保留明确标记的 review 状态。
- 列表、卡片、详情、编辑页和回收站显示编号。支持 `GC-000850`、`gc-850`、`850`、前导零与全角数字搜索；旧名称、分类等搜索保留。
- ZIP 的 `item_instances.csv` 和 `data.json` 自动包含编号字段；JSON 记录编号格式规则。

## 旧数据与部署

`supabase/migrations/*_inventory_codes.sql` 是一次性、兼容旧客户端的增量迁移：

1. 使用短事务和3秒锁等待上限锁定款式、实例表。忙碌时整次失败，不保持长锁等待用户操作。
2. 将原实例和款式逐行备份到 `private.inventory_code_backups`，客户端无读写权限。此备份是数据记录备份，不是图片文件的另一个副本。
3. 按每个家庭的 `created_at, id` 为所有现存实例补号，含回收站；不合并同名或同图记录。
4. 从最高旧编号初始化私有计数器。名称、原 ID、时间、位置、照片路径和关联关系均保留。
5. 更新资料完整度规则，不把“没起名字”视为未完成。
6. 在事务内对照备份校验记录数量及原字段；除新增编号和资料完整度以外，任一原字段变化就整次回滚。

先在 `gucang-test` 测试，再将同一 SQL 应用到 `gucang` 正式库，最后发布前端。无需修改 Vercel 的数据库环境变量。不可把连接测试库的预览构建直接提升为正式版，应让 main 使用 Production 配置重新构建。

迁移应只执行一次。MCP 应用迁移时会生成数据库版本号，发布前将仓库迁移文件版本对齐正式库记录；测试库历史版本号可能不同，不应据此重新初始化任何现有库。

如果回退前端，保留新增列和计数器即可兼容旧代码。不要重新跑补号、清零计数器或将迁移前备份整表覆盖到正在使用的数据库；这会丢掉迁移后的新记录和编辑。

## 验证

- `npm test`：编号格式/扩位、数字排序、旧名称与编号搜索、空名称完整保存、单实例更新、重试和图片保护。
- `npm run test:browser`：独立浏览器连接本地内存模拟服务；手机与桌面录入、选填折叠、旧名称保留、代码展示、搜索和回收站恢复。需按性能文档用本地测试变量构建服务，绝不发布这份本地构建产物。
- `supabase/tests/inventory_codes.sql`：仅在测试库执行。真实 PostgreSQL 下验证权限、同款多件、并发重试兼容的 upsert、不可改号、删除不复用、跨家庭隔离及7位扩展；全部新建测试对象在结束时回滚。
- 额外并发验收：测试库中新建专用临时谷仓，两路各12条并发写入得到24个不同编号；同一 UUID 两路重试都返回第25号，计数器保持25。随后只清理该临时谷仓，不清理原测试收藏。
- 迁移后的四条原测试实例已获1–4号，除新增字段外逐行与备份相同，原款式字段除完整度外相同。

数据库安全检查中，两个 private 表开启 RLS 且没有面向客户端的 policy 是刻意的拒绝访问设计，不应为了消除提示增加公开权限。已有 RPC 的 security-definer 提示和 Auth 密码安全设置不是本次新增权限；其说明见 [Supabase 数据库检查](https://supabase.com/docs/guides/database/database-linter?lint=0029_authenticated_security_definer_function_executable)及 [密码安全](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection)。

参考：[PostgreSQL 17 触发器与 upsert 行为](https://www.postgresql.org/docs/17/trigger-definition.html)、[Supabase 函数权限](https://supabase.com/docs/guides/database/functions)。
