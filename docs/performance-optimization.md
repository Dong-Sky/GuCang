# 新图与保存性能优化

## 边界

- 从正式代码 `b24bbc6` 建立 `feat/upload-performance`，不包含已废弃的滑动功能。
- 本轮没有数据库迁移，没有切换 Vercel/Supabase 环境，没有压缩、覆盖或迁移历史照片。
- 标准/高清只作用于本次选择的新文件；历史图片占用不会因为这次代码更新立即下降。
- 原有 7 天回收站规则不变，但清理逻辑不再位于每次保存的关键路径中。

## 实现

1. `lib/collection/` 保留可索引的元数据快照。保存只读取当前款式、持有实例、照片和相关字典/移动记录；合并时保留其他条目及其对象引用。位置保存返回新行，并在本地更新位置树与图片占用。
2. 首次进入/手动刷新仍完整读取元数据，以保证全局搜索、IP 分组及总数准确；API 每批最多 500 行，避免默认 1000 行截断。这不是只搜索已翻到的页。
3. 界面每页 24 条。图片接近可视区域 200px 时才签名与加载；详情才加载详情图。
4. 私有图片链接在当前用户/家庭的内存中缓存，1 小时有效、提前 1 分钟刷新；同路径请求合并，每批最多 48 个，缓存最多 512 个。退出或切换家庭后不共享这些链接。
5. 一次解码生成详情图和缩略图，支持时在 Worker + OffscreenCanvas 中处理；不支持或解码失败时回退到 HTMLImage + Canvas。每次最多两路图片上传，避免手机同时解码多张原图造成内存压力。
6. 显示“处理照片 → 保存资料 → 上传照片 → 更新列表”，上传阶段显示当前照片及已完成文件数，不伪造网络上传百分比。
7. 当前表单保存会话预留唯一款式、实例和图片 ID；失败重试复用会话，不重复新增。成功上传的文件不重传，已提交的图片元数据不重复提交。该重试会话目前是内存态：上传失败请在当前表单重试，不要关闭浏览器再重新录入；关闭页面可能留下本次未完成的上传文件，本轮不进行自动删除，避免误删数据。
8. 登录令牌刷新不再导致整个收藏空间重载。备份元数据也按批读取，避免大收藏导出到 1000 行时被截断。

## 新照片参数

| 模式 | 详情图最长边 | 缩略图最长边 | 编码质量起点 | 体积优化目标 |
| --- | --- | --- | --- | --- |
| 标准省空间（默认） | 1400px | 400px | 0.78 / 0.72 | 120KiB / 24KiB |
| 高清 | 1800px | 600px | 0.84 / 0.80 | 500KiB / 80KiB |

保持比例、不放大小图，优先 WebP；若浏览器不支持 WebP 编码则检查真实 MIME 并回退 JPEG。体积是优化目标而非硬限制：至多再编码一次，质量不低于预设下限，不为追求极小文件无限降质。真实大小随照片复杂度变化，不能据此保证每张都在 80–100KB。

## 回归结果（2026-08-30）

- TypeScript、ESLint、Next.js 生产构建通过。
- 13 个单元/隔离 API 测试通过：分页、1205 行完整读取、款式/实例局部合并、历史图片保留、私有签名缓存/到期/隔离、编码回退、并发上限、失败重试。
- 手机视口 390×844 与桌面 1440×1000 冒烟通过，无浏览器运行时异常。
- 已验证登录、卡片/列表分页、搜索第 1000 行以后的记录、资料编辑、标准/高清新图、Worker/兼容处理、上传失败重试、取出归位、待办切换、位置创建及编辑。
- 保存一件后未重新查询家庭成员或所有持有实例，未对全部历史图片重新签名。
- 模拟首次缩略图上传失败：最终仍只新增一个款式和实例，共三次文件上传（两次初始请求 + 一次失败文件重试）。同时上传峰值为 2。
- 1205 张历史图片元数据哈希前后一致，上传接口拒绝任何历史路径写入。
- 合成测试图片标准两图共 54,662 字节，高清共 86,278 字节；仅为功能样本，不代表真实照片的平均压缩率或真实网络耗时。
- 顺带修复根位置编辑时错误选择自身为上级，以及在待归位列表操作后不必要的页面返回。

未验证：真实安卓相机/相册的系统选择器、所有 HEIC 机型解码差异、正式网络实际吞吐。所有增删改测试只发生在本地内存夹具中。

## 重跑浏览器冒烟（本地专用）

Node 22.13+，需可用的 Playwright 和 Chromium/Chrome/Edge。浏览器测试启动独立临时配置，不读取用户浏览器登录会话，并阻止非 localhost 网络访问。

在 PowerShell 中构建并启动本地应用：

```powershell
$env:NEXT_PUBLIC_SUPABASE_URL = 'http://127.0.0.1:54339'
$env:NEXT_PUBLIC_SUPABASE_ANON_KEY = 'local-smoke-test-only'
npm run build
npm run start -- -H 127.0.0.1 -p 3100
```

在第二个终端中：

```powershell
# 如未安装在项目依赖中，指定 Playwright 的 index.mjs 绝对路径。
$env:GUCANG_PLAYWRIGHT_PATH = '<Playwright index.mjs 的绝对路径>'
# 可选：使用已安装的 Chromium 系浏览器可执行文件，而不是下载测试浏览器。
$env:GUCANG_BROWSER_EXECUTABLE = '<浏览器可执行文件绝对路径>'
npm run test:browser
```

脚本会自行在 54339 端口创建/关闭纯内存模拟服务。不要同时运行另一个 `tests/mock-supabase.mjs` 实例。截图保存在忽略提交的 `.local-test/`。本地测试构建含模拟 URL，不能 `vercel deploy --prebuilt`；正式发布应由 GitHub/Vercel 使用对应环境变量重新构建。
