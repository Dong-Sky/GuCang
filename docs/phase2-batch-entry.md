# 第二阶段：连续录入与批量整理（Preview）

基线 main a1a7316；分支 feat/phase2-batch-entry。用户确认后才能合并 main。

## 范围
- 新建支持「保存并继续」。默认沿用 IP、品类、系列、位置，可取消勾选；保留录入模式和画质。
- 下一件重新生成保存会话；不继承照片、编号、名称、角色和备注。未保存草稿仍按第一阶段机制保留。
- 位置详情「添加谷子到这里」；已有草稿优先，恢复草稿不会悄悄改写其位置。
- 收藏及待办提供批量整理；一次最多 50 件，选择本页仅选择本页，不隐式选择全库。
- 一次补一个字段：IP、品类、角色、系列或位置。只补空白；角色/系列必须匹配 IP。同款有未选择实物时不改共享资料。
- 批量归位到各件的默认位置。已归位、无可用默认位置的逐件跳过。
- 缺 IP/品类/位置/照片筛选；修改批量筛选清空选择，防止隐藏记录误操作。
- 确认页列出逐件影响/跳过原因；逐件执行，可停止后续任务、重试未完成项。不承诺整批事务回滚。

## 边界
- 无数据库迁移；不修改正式配置；Preview 构建保持 gucang-test 检查。
- 无批量删除、无批量覆盖、无图片改写、无编号重排。
- 一次选多张照片仍属于同一件，最多三张；不是自动按照片拆分入库。
- 批量字典值从已有资料选择，新值先单件建立。用户退出页面后批量结果面板不持久化，但已完成操作保留。
- 浏览器与 API 测试只访问 localhost 合成数据，不登录真实业务账号执行写入。
- 预览发布不涉及正式库备份轮换；未来合并前最新业务备份校验成功后仅保留最新三份，最旧整份移入回收站，不清空。

## 测试
- 单元/隔离 API：字段继承白名单、只补空白、同款保护、逐件归位、重试不重复移动、失败/成功分开、取消、50 件上限、历史照片不变。
- 浏览器 390/1280：从位置添加、连续保存两件独立编号、下一件无原图、批量预览/位置补充/不覆盖。
- 回归第一阶段草稿、原照片专项及完整冒烟。
